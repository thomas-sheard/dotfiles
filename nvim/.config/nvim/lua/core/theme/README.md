Semantic colours are exposed through `palette.lua`, which is auto-generated by the theme engine.

These are given semantic roles in `roles.lua`, which is where the theming ethos (below) is enforced. 
This is where changes to the highlighting ethos can be defined (eg. changing functions to be orange).

These roles are exposed to `groups` and `ui.lua`, which assign highlight groups, TreeSitter captures, and semantic tokens to semantic roles; things that do things, information, etcetera.
This is where erroneous highlight groups should be fixed (eg. this function isn't being coloured correctly).
Use `:Inspect` to classify the highlight group, and follow the shape of the suitable file to fix it.

Use `:ThemeAudit`, exposed by `audit.lua`, to find any active highlight groups that are not using or linked in some way to the semantic roles.

The rest of the files are machinery to then apply and validate the theme.
